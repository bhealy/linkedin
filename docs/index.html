What is LinkedIn Connection Cleaner?

A local Node.js toolkit — dashboard first, CLI still available — for exporting, understanding, and cleaning your LinkedIn network.

LinkedIn does not offer a good way to bulk-export or bulk-remove a large network, or to find 1st-degree connections who messaged you and never got a reply. This project fills that gap on your own computer.

Dashboard → Download → Inbox → Review → Remove

Recommended workflow

  • Run npm start and save your email
  • Download connections.csv
  • Cache the inbox, then search for unrequited love
  • Protect contacts, dry-run, then execute

Requirements

  • Node.js 18 or later
  • Google Chrome installed
  • A LinkedIn account
  • macOS, Windows, or Linux

Install and open the dashboard

Clone the repo, install dependencies, then work in the local UI.

git clone https://github.com/bhealy/linkedin.git
cd linkedin
npm install
cp .env.example .env
npm start

Edit .env with your LinkedIn login email, or save it from the dashboard:

LINKEDIN_EMAIL=you@example.com

The dashboard listens only on http://127.0.0.1:3847/. Your password is sent only for the job that needs it and is never written to .env. Running jobs show a live ETA in the Jobs pane.

💡
Optional: paste your li_at cookie from Chrome DevTools into LI_AT in .env. It is injected only when the saved Chrome profile has no session. If LinkedIn rejects it, a login window still opens.

Jobs launch your installed Google Chrome, not Puppeteer's bundled Chrome-for-Testing build. The bundled build advertises itself as automated (navigator.webdriver) and often draws a captcha; Brave or normal Chrome on the same machine does not. Session files live in .linkedin-session/.

Download your connections

Export your full 1st-degree network. This CSV is required before inbox search.

npm start   # then use Download connections
# or
npm run connections:download

The downloader opens your connections page, then paginates via LinkedIn's SDUI API. Results are written to connections.csv after every batch. Progress is saved so you can stop and resume.

⚡
5,000 new contacts per run. Each run fetches up to 5,000 new connections. Run again until the summary says the list is complete. Optional: last N months only with --months.
CommandPurpose
npm run connections:downloadContinue or start download
npm run connections:download:statusShow saved progress
npm run connections:download:freshReset CSV and state
node download-connections.js --limit 100Fetch only 100 new (for testing)
node download-connections.js --resumeContinue if wrongly marked complete

CSV columns: name, title, profile_url, vanity_name, connected_on

Cache the inbox, then search

Find 1st-degree connections who sent at least one message in a 1:1 thread and never got a reply from you.

The dashboard locks Search for unrequited love until Cache conversation list has paged to the oldest conversation. Cache uses LinkedIn's conversation list API and does not open threads. Search opens threads in parallel Chrome tabs (default 4).

npm run inbox:cache
npm run inbox:scan
npm run inbox:scan -- --days 90 --tabs 1 --limit 50
⚠️
Page-open budget: 2,000 conversation pages per hour, 4,000 per 4 hours. The dashboard shows the count. When the cap is hit, come back later, schedule a slower scan (1 tab), or override. LinkedIn may still challenge the account if you go over. --pace-page-budget waits instead of pausing.

LinkedIn's own Connections inbox filter is not used — it stops after about 100 threads. Group chats are skipped. Output is unrequited-love.csv. Nothing is removed by the search itself.

Analytics

Inspect connections and cached conversations without leaving the dashboard.

Open the Analytics tab. Filter connections by date; filter conversations by status, activity window, unrequited vs replied, and search. Charts update for the list you are viewing.

Optionally export a standalone HTML file:

npm run connections:analytics:open
🔐
The analytics HTML embeds your contact list. Keep it private — don't upload it to public hosting.

Review and remove

Protect people first. Dry-run always. Execute is a separate, confirmed action.

Use Review & protect contacts to browse the selected CSV and tick Protect. That writes a protected column; every removal run skips those rows.

For unrequited-love.csv, only people who sent more than one unanswered message are included by default. Tick “Include people who sent only one message” (or --include-single-message) to widen that. Founder / CEO / investor titles are protected unless you turn that off.

# Dry run
npm run connections:remove -- --csv unrequited-love.csv --limit 20

# Execute
npm run connections:remove -- --execute --csv unrequited-love.csv --limit 20
FlagDescription
--executeActually remove (omit for dry run)
--statusspam, sales, recruitment, not_target, etc.
--include-single-messageAlso remove 1-message unrequited threads
--safe-keywordsExtra protected title phrases
--no-unrequited-safe-listTurn off the default title safe list
--ignore-companySkip headlines mentioning this company
⚠️
Removals are permanent on LinkedIn. Always dry-run first with a small --limit. Removals are spaced ~1.2 seconds apart.

Optional tools

Title-based people search and single-profile archive. Skip these for the main cleanup path.

Sales / recruitment scrape walks a keyword × geography grid in search-plan.json (LinkedIn caps search at ~250 hits per query). Output: sales-connections.csv.

npm run scrape:sales
npm run scrape:status

Each contact is classified as sales recruitment sales_and_recruitment not_target

Archive one profile to JSON + HTML under profiles/:

npm run profile:scrape -- https://www.linkedin.com/in/your-vanity/
npm run profile:html:open

Privacy, login, and limits

Your data stays on your machine. LinkedIn still sees the traffic from your account.

🔒 Local-only execution

Puppeteer drives Google Chrome on your computer. Nothing is proxied through a third party. The dashboard binds to localhost only.

🚫 Never commit secrets

.env, CSVs, analytics HTML, inbox-page-opens.json, and .linkedin-session/ are gitignored. Never push these to GitHub.

🌐 Chrome, not Chrome for Testing

The bundled Puppeteer browser reports itself as automated. Installed Chrome with automation switches off is what this project launches.

⏱ Pace inbox search

Stay inside 2,000 page opens per hour. After a large scan, LinkedIn may still show a captcha even in a clean browser — that is behavioural, not just fingerprint.

Architecture

How it works under the hood

A quick technical overview for the curious.

Local dashboard

npm start serves ui/public on 127.0.0.1:3847. Jobs are child processes. Status includes live ETAs, inbox page-open budget, and a scheduled slower scan when the cap is hit.

Connections downloader

Uses Puppeteer with installed Chrome, then calls POST /flagship-web/rsc-action/actions/pagination on the connections page. Responses are React Flight / SDUI streams parsed for name, title, profile URL, and connection date.

Inbox cache and search

Cache pages the conversation list API into unrequited-love.csv. Search opens threads in parallel tabs, counts inbound vs outbound messages, and flags unanswered inbound. Page opens are recorded in inbox-page-opens.json.

Analytics

The dashboard charts connections and conversations live. Optionally render a self-contained HTML file with Chart.js from connections.csv.

People search scraper

Optional. Navigates people search for each keyword × geography cell in search-plan.json. LinkedIn caps search at ~250 results per query; the grid works around this.

Bulk removal

Calls LinkedIn's SDUI remove-connection action for each vanity_name. Skips protected rows, ignored companies, and (for inbox CSVs) the title safe list unless disabled. Tracks removed profiles so reruns skip them.
