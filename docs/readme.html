Executive summary

LinkedIn Connection Cleaner is a set of Node.js scripts that run on your computer. They log into LinkedIn in a local Chromium window (Puppeteer), export your 1st-degree connections, build a private analytics page, optionally find sales/recruitment contacts, and can bulk-remove connections you no longer want. Nothing is uploaded to this site or any third-party API.

LinkedIn does not give you a good bulk-export or bulk-remove UI for a large network. This toolkit pages through your connections list, writes a CSV, and lets you inspect that CSV before you delete anything. Removals default to dry-run until you pass --execute.

Who it is for

People with a large LinkedIn network who want a local CSV, charts, and controlled cleanup — not a hosted SaaS product.

What you get

A connections.csv file, a self-contained connections-analytics.html dashboard, optional classified search results, and optional disconnects.

What stays private

Your password is typed at the terminal, not stored. Session cookies live in .linkedin-session/. CSVs and analytics HTML are gitignored. Do not commit or publish them.

What to expect

Each download run caps at 5,000 new contacts. Requests are delayed to reduce rate limits. Automation still carries risk — start small.

The default path

  1. Install Node.js 18+, clone the repo, npm install, copy .env.example to .env, set LINKEDIN_EMAIL. Or run npm start and use the local dashboard at http://127.0.0.1:3847/.
  2. Run npm run connections:download (repeat until the summary says the list is complete, or use --months N for recent contacts only).
  3. Run npm run connections:analytics:open and explore the dashboard locally.
  4. Optional: npm run scrape:sales to classify sales/recruitment via people search.
  5. Dry-run removals, then execute: npm run connections:remove -- --status spam --limit 20 then add --execute when you are sure.
git clone https://github.com/bhealy/linkedin.git
cd linkedin
npm install
cp .env.example .env
# edit .env: LINKEDIN_EMAIL=you@example.com
npm run connections:download
npm run connections:analytics:open

1. Install

Requires Node.js 18+ and a LinkedIn account. Puppeteer downloads Chromium on npm install.

git clone https://github.com/bhealy/linkedin.git
cd linkedin
npm install
cp .env.example .env

Put only your login email in .env:

LINKEDIN_EMAIL=you@example.com

Optional: set LI_AT to your LinkedIn li_at cookie to skip the password prompt. On first run without that cookie, a browser window opens; complete login (and any checkpoint) there. The session is reused from .linkedin-session/.

For a clickable UI on your Mac, run npm start and use http://127.0.0.1:3847/ (localhost only). Password is sent per job and is not stored in .env.

2. Download your connections

This is the main export. It opens the connections page and paginates LinkedIn’s list newest first via the SDUI pagination API. Rows are appended to connections.csv after every batch. Progress is stored in download-connections-state.json so you can stop and continue.

npm run connections:download
npm run connections:download:status
npm run connections:download:fresh
node download-connections.js --resume
node download-connections.js --limit 100

Each run fetches up to 5,000 new contacts (not 5,000 total). Run again until the summary says the list is exhausted. Batches wait a random 1–10 seconds.

CSV columnMeaning
nameDisplay name
titleHeadline
profile_urlProfile URL
vanity_nameSlug used for removals
connected_onLinkedIn “Connected on” date

3. Only the last N months

Because the list is newest first, --months N starts at the top and stops paging once a batch is entirely older than today minus N calendar months. That avoids walking your whole archive.

npm run connections:download -- --fresh --months 6
npm run connections:download -- --months 3 --limit 5000

Use --fresh --months N when you want a CSV that only contains that window. Without --fresh, older rows already in the CSV are kept. After the window is complete, --resume (without --months) continues into older contacts. Blank dates are not used as a stop signal.

4. Analytics dashboard

Turns connections.csv into a single local HTML file: growth by month, roles and seniority inferred from headlines, top companies and keywords, weekday patterns, and a searchable table.

npm run connections:analytics:open
node generate-connections-analytics.js --input connections.csv --output report.html --open

That HTML embeds your contacts. Open it only on your machine. Do not host it publicly.

5. Optional: scrape by job title

People search is capped at about 250 hits per query. npm run scrape:sales walks a keyword × geography grid in search-plan.json and classifies each person as sales, recruitment, sales_and_recruitment, or not_target. Output: sales-connections.csv. Skip this if you only want a full export and charts.

npm run scrape:sales
npm run scrape:status
npm run scrape:sales:fresh

6. Search for unrequited love

Opens LinkedIn Messaging and lists every conversation, matching each name against connections.csv to decide who is a connection, then reads the matched threads whose latest activity falls inside --days (default 30). LinkedIn’s own Connections inbox filter is not used: it stops serving results after roughly 100 threads, so it hides most of your history. Download your connections before searching, and group threads are skipped. Threads are opened in parallel Chromium tabs (default 4) and scrolled to the top. A conversation is stored in unrequited-love.csv the first time it is seen. Later runs skip threads whose last activity has not changed.

A connection becomes a candidate only when they sent at least one message and you sent none in that thread. Candidate rows are the ones the Remove card uses; replied and listed rows stay in the same CSV as the cache. Nothing is removed by the search itself. Successful removals are immediately marked disconnected=yes with a timestamp in this CSV, so later searches and removal runs skip them without losing the conversation history.

Use Cache conversation list (--cache) once to scroll the whole inbox and save every connection conversation without opening threads. After that, a search only loads the latest messages until it catches up with the cache, then decides from the CSV which threads still need a read.

npm run inbox:cache
npm run inbox:scan
npm run inbox:scan -- --days 90 --limit 50 --tabs 4
npm run inbox:scan:status
npm run inbox:scan -- --fresh

Every message counts, including attachments and emoji, so an image-only reply from you still protects that connection from being flagged. A matched conversation inherits the profile URL from connections.csv; where two connections share a name, the candidate's profile is visited once to resolve the vanity name before it is ready to remove.

FlagDescription
--daysHow far back to look, by last activity (default 30)
--limitMax conversations to open this run
--tabsParallel Chromium tabs for reading threads (default 4)
--cacheScroll the whole conversation list into the CSV without opening threads
--csvOutput path (default unrequited-love.csv)
--freshBack up, then reset the CSV and scan state
--statusPrint scanned, found and ready-to-remove counts

Review the CSV, then hand it to the remover — dry run first:

npm run connections:remove -- --csv unrequited-love.csv --limit 20
npm run connections:remove -- --execute --csv unrequited-love.csv --limit 20

7. Bulk remove

Omit --execute to print who would be removed. Removals are permanent on LinkedIn. When the source is an inbox CSV such as unrequited-love.csv, a safe list is on by default and protects founders, C-suite leaders, investors, board members and selected owner/partner roles. Add protected phrases with --safe-keywords, or deliberately disable this protection with --no-unrequited-safe-list. The dry run reports protected and would-remove counts. Default ignored company names in headlines: Manna and Meili (add more with --ignore-company). Spacing is about 1.2 seconds between removals. Removed vanity names are remembered and marked in both the source inbox CSV and master connections.csv, so later runs skip them.

npm run connections:remove -- --status spam --limit 20
npm run connections:remove -- --execute --status spam --limit 20
npm run connections:remove -- --execute --status sales --limit 50

--status spam is sales + recruitment + both. You can also pass a single status or not_target.

FlagDescription
--executeActually disconnect (otherwise dry-run)
--statusspam, sales, recruitment, sales_and_recruitment, not_target
--limitMax people this run
--ignore-companySkip headlines that mention this company (repeatable)
--safe-keywordsAdd comma-separated protected title words or phrases for inbox CSV removals
--no-unrequited-safe-listTurn off the default protected-title list for inbox CSV removals
--csvDifferent input CSV
--freshClear removal history

8. Archive one profile

Exports a single public profile to JSON plus a self-contained HTML page under profiles/ (gitignored). Default visit is experience, education, and skills (~30–45s). --full-details hits every detail sub-page.

npm run profile:scrape -- https://www.linkedin.com/in/your-vanity/
node scrape-profile.js --skip-details
node scrape-profile.js --full-details
npm run profile:html:open

⚠️
This is unofficial automation against LinkedIn’s website. Pace yourself, dry-run removals, and use it at your own discretion. Rate limits and account restrictions are possible.
