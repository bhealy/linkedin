Executive summary

LinkedIn Connection Cleaner is a Node.js toolkit that runs on your computer. The recommended front end is a localhost dashboard (npm start → http://127.0.0.1:3847/). Jobs log into LinkedIn in your installed Google Chrome (not Puppeteer's Chrome-for-Testing build), export your 1st-degree connections, cache messaging, flag unanswered inbound threads (“unrequited love”), show live analytics and job ETAs, and can bulk-remove connections you have previewed. Nothing is uploaded to this site or any third-party API.

LinkedIn does not give you a good bulk-export or bulk-remove UI for a large network, and its Connections inbox filter stops after about 100 threads. This toolkit writes CSVs you can inspect before you delete anything. Removals default to dry-run until you pass --execute (or confirm in the dashboard).

Who it is for

People with a large LinkedIn network who want a local CSV, inbox cleanup, charts, and controlled disconnects — not a hosted SaaS product.

What you get

A dashboard, connections.csv, unrequited-love.csv, optional analytics HTML, optional sales scrape, and optional disconnects with protect flags.

What stays private

Password is never stored in .env. Session cookies live in .linkedin-session/. CSVs, inbox-page-opens.json, and analytics HTML are gitignored.

What to expect

Download runs cap at 5,000 new contacts. Inbox search caps conversation page opens at 2,000/hour and 4,000/4 hours. Automation still carries risk — start small, use 1 tab if challenged.

The default path

  1. Install Node.js 18+, Google Chrome, clone the repo, npm install, copy .env.example to .env, set LINKEDIN_EMAIL. Run npm start.
  2. Download connections (repeat until complete, or use --months N).
  3. Cache the conversation list, then search for unrequited love.
  4. Review & protect contacts. Dry-run removals, then execute.
  5. Optional: analytics HTML, sales scrape, or a single-profile archive.
git clone https://github.com/bhealy/linkedin.git
cd linkedin
npm install
cp .env.example .env
# edit .env: LINKEDIN_EMAIL=you@example.com
npm start
# open http://127.0.0.1:3847/

1. Install

Requires Node.js 18+, Google Chrome, and a LinkedIn account. Puppeteer still downloads its own Chrome-for-Testing binary on npm install, but jobs launch the Chrome app already on your machine.

git clone https://github.com/bhealy/linkedin.git
cd linkedin
npm install
cp .env.example .env

Put only your login email in .env:

LINKEDIN_EMAIL=you@example.com

Optional: set LI_AT to your LinkedIn li_at cookie. It is injected only when .linkedin-session/ has no session, and only accepted if LinkedIn does not redirect to login, authwall, or checkpoint. A stale cookie cannot displace a working saved login. If it is rejected, sign in in the Chrome window.

2. Local dashboard

Run npm start and open http://127.0.0.1:3847/ (localhost only). The Activity tab is the journey: login → download → cache inbox → search → review → remove. The Analytics tab charts connections and conversations with filters. Jobs show live status and an ETA. Only one job runs at a time. Stop / pause for now keeps CSV and cache progress.

Password is sent per job and is not stored in .env. You can remember it in this browser for 30 days (local storage on this machine only).

When the conversation page-open cap is hit, the dashboard offers come back later, schedule a slower scan (fewer tabs, waits until the cap eases), or override.

3. Download your connections

This is the main export. It opens the connections page and paginates LinkedIn’s list newest first via the SDUI pagination API. Rows are appended to connections.csv after every batch. Progress is stored in download-connections-state.json so you can stop and continue.

npm run connections:download
npm run connections:download:status
npm run connections:download:fresh
node download-connections.js --resume
node download-connections.js --limit 100

Each run fetches up to 5,000 new contacts (not 5,000 total). Run again until the summary says the list is exhausted. Batches wait a random 1–10 seconds.

CSV columnMeaning
nameDisplay name
titleHeadline
profile_urlProfile URL
vanity_nameSlug used for removals

4. Only the last N months

Because the list is newest first, --months N starts at the top and stops paging once a batch is entirely older than today minus N calendar months. That avoids walking your whole archive.

npm run connections:download -- --fresh --months 6
npm run connections:download -- --months 3 --limit 5000

Use --fresh --months N when you want a CSV that only contains that window. Without --fresh, older rows already in the CSV are kept. After the window is complete, --resume (without --months) continues into older contacts. Blank dates are not used as a stop signal.

5. Analytics

The dashboard Analytics tab charts connections (date filters, roles, seniority, companies) and cached conversations (status, activity window, explorer). Optionally turn connections.csv into a single local HTML file:

npm run connections:analytics:open
node generate-connections-analytics.js --input connections.csv --output report.html --open

That HTML embeds your contacts. Open it only on your machine. Do not host it publicly.

6. Optional: scrape by job title

People search is capped at about 250 hits per query. npm run scrape:sales walks a keyword × geography grid in search-plan.json and classifies each person as sales, recruitment, sales_and_recruitment, or not_target. Output: sales-connections.csv. Skip this if you only want a full export and charts.

npm run scrape:sales
npm run scrape:status
npm run scrape:sales:fresh

7. Search for unrequited love

Opens LinkedIn Messaging and lists every conversation, matching each name against connections.csv to decide who is a connection, then reads the matched threads whose latest activity falls inside --days (default 30). LinkedIn’s own Connections inbox filter is not used: it stops serving results after roughly 100 threads, so it hides most of your history. Download your connections before searching, and group threads are skipped. Threads are opened in parallel Chrome tabs (default 4) and scrolled to the top. A conversation is stored in unrequited-love.csv the first time it is seen. Later runs skip threads whose last activity has not changed.

A connection becomes a candidate only when they sent at least one message and you sent none in that thread. Candidate rows are the ones the Remove card uses; replied and listed rows stay in the same CSV as the cache. Nothing is removed by the search itself. Successful removals are immediately marked disconnected=yes with a timestamp in this CSV, so later searches and removal runs skip them without losing the conversation history.

Use Cache conversation list first. Search stays locked until that pass reaches the oldest conversation. The cache pages the inbox via LinkedIn’s conversation list API and saves every connection conversation without opening threads. Stop / pause for now keeps the CSV and the list cursor. Run cache again to resume older pages instead of starting over. After the list is complete, a search only loads the latest messages until it catches up with the cache, then decides from the CSV which threads still need a read.

Opening conversation pages is capped at 2,000 per hour and 4,000 per 4 hours. The dashboard shows the count and warns that LinkedIn may block the account if you go over. The search pauses when the cap is hit; you can come back later to resume, schedule a slower scan with fewer tabs, or override the limit.

npm run inbox:cache
npm run inbox:scan
npm run inbox:scan -- --days 90 --limit 50 --tabs 4
npm run inbox:scan:status
npm run inbox:cache -- --fresh

Every message counts, including attachments and emoji, so an image-only reply from you still protects that connection from being flagged. A matched conversation inherits the profile URL from connections.csv; where two connections share a name, the candidate's profile is visited once to resolve the vanity name before it is ready to remove.

FlagDescription
--daysHow far back to look, by last activity (default 30)
--limitMax conversations to open this run
--tabsParallel Chrome tabs for reading threads (default 4)
--override-page-budgetIgnore the 2,000/hour and 4,000/4-hour conversation-page cap
--pace-page-budgetWait for the cap to ease instead of pausing
--cachePage the conversation list into the CSV without opening threads. Re-running resumes from the last saved page
--csvOutput path (default unrequited-love.csv)
--freshBack up, then reset the CSV and scan state
--statusPrint scanned, found and ready-to-remove counts

Review the CSV, then hand it to the remover — dry run first:

npm run connections:remove -- --csv unrequited-love.csv --limit 20
npm run connections:remove -- --execute --csv unrequited-love.csv --limit 20

8. Bulk remove

Omit --execute to print who would be removed. Removals are permanent on LinkedIn. Use Review & protect contacts to browse or search the full selected source CSV and protect individual contacts; that choice is stored in the CSV’s protected column and all removal runs skip those rows. When the source is an inbox CSV such as unrequited-love.csv, only people who sent more than one unanswered message are included by default. Pass --include-single-message to also remove people who sent a single unanswered message. A safe list is on by default and protects founders, C-suite leaders, investors, board members and selected owner/partner roles. Add protected phrases with --safe-keywords, or deliberately disable this protection with --no-unrequited-safe-list. The dry run reports protected and would-remove counts. Default ignored company names in headlines: Manna and Meili (add more with --ignore-company). Spacing is about 1.2 seconds between removals. Removed vanity names are remembered and marked in both the source inbox CSV and master connections.csv, so later runs skip them.

npm run connections:remove -- --status spam --limit 20
npm run connections:remove -- --execute --status spam --limit 20
npm run connections:remove -- --execute --status sales --limit 50

--status spam is sales + recruitment + both. You can also pass a single status or not_target.

FlagDescription
--executeActually disconnect (otherwise dry-run)
--statusspam, sales, recruitment, sales_and_recruitment, not_target
--limitMax people this run
--ignore-companySkip headlines that mention this company (repeatable)
--safe-keywordsAdd comma-separated protected title words or phrases for inbox CSV removals
--no-unrequited-safe-listTurn off the default protected-title list for inbox CSV removals
--include-single-messageAlso remove unrequited connections who sent only one unanswered message (default is 2+)
--csvDifferent input CSV
--freshClear removal history

9. Archive one profile

Exports a single public profile to JSON plus a self-contained HTML page under profiles/ (gitignored). Default visit is experience, education, and skills (~30–45s). --full-details hits every detail sub-page.

npm run profile:scrape -- https://www.linkedin.com/in/your-vanity/
node scrape-profile.js --skip-details
node scrape-profile.js --full-details
npm run profile:html:open
